✅ COMPLETE ARRAY NOTES — BULLET POINT FORMAT
🔷 1. Arrays in Java — Core Concept

Arrays are objects, not primitives.

An object must come from a class → therefore:

Arrays have classes, but

These classes are hidden JVM-generated classes, not written by Java developers.

Arrays are built-in language constructs, not normal classes like String or Student.

🔷 2. Why arrays are not normal Java classes

Designed for speed and simplicity.

JVM handles them at a native level for faster indexing.

Avoid overhead of method lookups, vtables, inheritance.

Syntax like arr[i] implemented at JVM level, not via methods.

Interoperability with C-style array design.

🔷 3. JVM Internal Class Names for Arrays

Primitive arrays:

int[] → [I

float[] → [F

double[] → [D

char[] → [C

byte[] → [B

short[] → [S

long[] → [J

boolean[] → [Z

Reference (object) arrays:

String[] → [Ljava/lang/String;

Student[] → [Lyour/package/Student;

🔷 4. How to check array class
arr.getClass().getName();


Output shows the internal JVM array type (e.g., [I).

🔷 5. Fields available in an array

Arrays have exactly one field:

length → int

Stores number of elements in the array.

Is a field, not a method.

That is why you write arr.length (no parentheses).

🔷 6. Methods available to arrays

Arrays do NOT declare methods of their own.

They inherit methods from java.lang.Object:

clone()

getClass()

hashCode()

equals(Object)

toString()

finalize() (deprecated)

🔷 7. Why arr.length is field but str.length() is method

Arrays = built-in object → simple → use field length

String = normal Java class → uses a method length()

Designed differently for performance and flexibility.

🔷 8. Array Memory Layout (in JVM Heap)
Generic layout:
[Object Header]
[length]
[elements...]

🔷 9. Memory Diagram — Primitive Array (int[] a = new int[5])

Primitive array stores values directly in memory.

Stack → holds reference variable a

Heap → holds array object:

object header

length field

5 int values (all default 0)

🔷 10. Memory Diagram — Object Array (String[] s = new String[3])

Array stores references (pointers), not actual objects.

Default values stored = null

Each element must be assigned separately:

s[0] = "Apple";

🔷 11. Arrays are fixed size

Once created, size cannot change.

Because length is final internally.

🔷 12. Arrays and inheritance

Arrays are covariant (dangerous feature):

String[] is a subtype of Object[]

But JVM ensures type safety at runtime and may throw:

ArrayStoreException

🔷 13. Arrays vs java.util.Arrays
Arrays (like int[], String[])

One field: length

Only methods inherited from Object

Created using new keyword

Store elements directly/references

java.util.Arrays (utility class)

Contains static helper methods like:

sort()

binarySearch()

copyOf()

equals()

deepEquals()

fill()

toString()

deepToString()

Not related to array structure itself.

🔷 14. Arrays support cloning

Because they override clone() from Object.

int[] b = a.clone();


Produces a shallow copy.

🔷 15. Arrays support reflection

You can get:

element type

array size

component type

arr.getClass().getComponentType();

🔷 16. Multi-dimensional Arrays

Java uses arrays of arrays, not true multi-dimensional arrays.

Example:

int[][] a = new int[3][2];


Memory layout:

a → array of references to 3 separate 1D arrays.

Each row can have different sizes (jagged arrays).

🔷 17. Default values in arrays
Type	Default
int	0
float	0.0f
double	0.0
char	'\u0000'
boolean	false
object references	null
🔷 18. Characteristics of Arrays

Fast O(1) access by index.

Fixed size.

Contiguous memory for primitives.

Reference elements for object arrays.

Cannot grow → not flexible like ArrayList.

🔷 19. Common exceptions

ArrayIndexOutOfBoundsException

NullPointerException (when array ref is null)

ArrayStoreException (when storing wrong type)

🔷 20. Why arrays behave differently from ArrayList

ArrayList is a class implemented using dynamic arrays.

ArrayList supports:

add()

remove()

contains()

resize automatically

Array ≠ ArrayList.

🔷 21. Summary: What arrays truly are

Special objects created by JVM

Backed by hidden internal classes (like [I)

Have only 1 field (length)

Inherit basic Object methods

Store primitives directly

Store object references indirectly

Fast but fixed-size structures

🔷 22. Quick One-Page Summary (for revision)

Arrays are objects, not classes.

Array classes are auto-generated by JVM.

Internal names: [I, [F, [Ljava/lang/String; etc.

Only one field: length.

Inherited methods only (clone, getClass, hashCode, equals).

length → field ; length() → method (String).

Primitive arrays store values → directly.

Object arrays store references.

Arrays have fixed size.

Multi-dimensional arrays = arrays of arrays.

Default values depend on type.

Related but separate: java.util.Arrays utility class.

Exceptions: AIOOBE, NPE, ArrayStoreException.


-----------------------------------------------------------------------------------------------------------------------------------------------------
❌ Printing array directly (System.out.println(arr))

Prints memory-style value

Format:

Primitive array → [I@hashcode

Object array → [Ljava.lang.Object;@hashcode

Reason: Arrays do not override Object.toString()

✅ Arrays.toString(arr)

Static helper method in java.util.Arrays

Works for 1D arrays only

Prints in readable format:

[1, 2, 3, 4]


Converts each element to string and joins with commas

✅ Arrays.deepToString(arr)

For multi-dimensional arrays

Recursively prints nested arrays

Output example:

[[1, 2], [3, 4]]

🔍 Difference Between toString() and deepToString()

toString() → prints array reference for inner arrays

deepToString() → prints full nested structure

🚀 Java Arrays.sort() — Quick Revision Cheat Sheet
✅ 1. Default Behavior

Arrays.sort() always sorts in ASCENDING order.

✔ Primitive arrays
Arrays.sort(intArr);     // ascending
Arrays.sort(doubleArr);  // ascending
Arrays.sort(charArr);    // ascending

✔ Object arrays (String, Integer, etc.)
Arrays.sort(strArr);   // alphabetical ascending
Arrays.sort(intObjArr); // numeric ascending

🔽 2. Sorting in DESCENDING Order
✔ Works ONLY for Object arrays
Arrays.sort(arr, Collections.reverseOrder());


Example:

Integer[] nums = {5, 1, 4};
Arrays.sort(nums, Collections.reverseOrder());


Result:

[5, 4, 1]

❌ Not allowed for primitive arrays
int[] a = {5,1,4};
Arrays.sort(a, Collections.reverseOrder()); // ERROR

🔄 3. How to sort primitive array in descending?
Option 1: Convert to wrapper type
int[] a = {5, 1, 4};
Integer[] b = Arrays.stream(a).boxed().toArray(Integer[]::new);
Arrays.sort(b, Collections.reverseOrder());

🧠 4. Custom Sorting (Comparator)
✔ Custom comparator for object arrays:
Arrays.sort(arr, (a, b) -> b - a);  // descending
Arrays.sort(arr, (a, b) -> a - b);  // ascending

✔ Custom sorting for strings:
Arrays.sort(strArr, (a, b) -> b.compareTo(a)); // reverse alphabetical

📌 5. Sorting Subarrays

Sort only a range:

Arrays.sort(arr, fromIndex, toIndex);


Example:

Arrays.sort(arr, 2, 5); // sort indices 2 to 4

⚙️ 6. Performance

Uses Dual-Pivot Quicksort for primitives

Uses Timsort for object arrays

Time complexity: O(n log n)

✔ 7. Summary Table

Integer[], String[], etc.	Arrays.sort(arr)	Ascending
